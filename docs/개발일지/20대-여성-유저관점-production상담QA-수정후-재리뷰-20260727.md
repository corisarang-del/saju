# 20대 여성 유저관점 production상담QA 수정후 재리뷰

## 요청
- 개발자가 다시 피드백을 받아 수정한 뒤, 20대 여성 유저 관점에서 다시 리뷰해달라는 요청을 받았어.
- 깔려있는 스킬 중 적절한 스킬을 써도 된다는 조건이 있었어.
- 소스코드는 절대 건드리지 말라는 조건이 있었어.
- 지금까지 나온 내용을 문서화하고 메모리에 저장해달라는 요청도 함께 받았어.

## 사용한 스킬
- `design-taste-frontend`: 20대 여성 유저가 실제 화면/상담 경험에서 느끼는 완성도, 피로도, 결제 전환 감각을 판단하는 기준으로 사용했어.
- `memory`: 지금까지 나온 QA, 수정, 잔여 이슈를 프로젝트 메모리에 이어서 저장하는 기준으로 사용했어.
- `doc`: 개발자에게 전달하기 쉬운 문서 구조로 정리하는 기준으로 사용했어.

## 진행 범위
- 소스코드는 수정하지 않았어.
- 최신 `git status`, 프로젝트 메모리, learnings, production QA 문서, PM 전달 문서, 수정된 테스트/스크립트 내용을 읽었어.
- 이번 최신 수정의 핵심은 live QA 초기 프롬프트 source of truth 통합, 구버전 첫 질문도 첫 상담 품질 게이트로 처리, fallback 문장 차별화, `아웃풋` 같은 외래어 차단 보강이야.
- 이번 리뷰에서는 새 production live QA를 직접 다시 돌리지는 않았어. 그래서 실제 배포 반영 여부와 30초 안쪽 응답 달성 여부는 별도 재검증이 필요해.

## 20대 여성 유저 관점 총평
- 방향은 좋아졌어. 이전에는 "상담은 되는데 답변이 너무 늦고, 상담사별 문장이 비슷해서 상품성이 약하다"가 핵심 불안이었는데, 이번 수정은 그중 품질 기준 불일치와 fallback 반복 문제를 정확히 겨냥했어.
- live QA 스크립트가 앱의 최신 초기 프롬프트를 같이 쓰게 된 건 중요해. 테스트와 실제 앱이 다른 질문으로 합격/불합격을 판단하면 유저 경험이 안정됐다고 믿기 어렵거든.
- 첫 대화가 어떤 문구로 시작하든 첫 상담 품질 게이트를 타게 한 것도 좋아. 20대 유저는 캐시된 화면, 뒤로가기, 재접속 같은 다양한 경로로 들어올 수 있어서 최신 클라이언트만 가정하면 안 돼.
- fallback이 캐릭터별로 분리된 점은 유료 전환에 좋아. 유료 상담앱은 "어차피 다 같은 AI 답변"처럼 느껴지는 순간 돈 낼 이유가 약해지는데, 이번 수정은 그 의심을 줄이는 쪽이야.
- 다만 아직 가장 큰 소비자 리스크는 응답 속도야. 직전 production QA에서 7명 캐릭터 응답이 37.9초~52.9초였기 때문에, 실제 배포 후에도 이 정도면 무료 체험 만족도와 결제 의향이 크게 깎여.

## 분위기와 느낌
- 제품 분위기는 여전히 20대 여성에게 부담이 낮은 편이야. 사주앱 특유의 무섭고 단정적인 톤보다, 고민을 정리해주는 조용한 상담 앱에 가까워.
- 이번 수정은 화면의 예쁨보다는 상담 신뢰 쪽을 건드렸어. 그래서 겉으로 바로 보이는 변화보다 "답변이 이상하게 끊기거나, 문장이 어색하거나, 상담사들이 다 똑같아 보이는 느낌"을 줄이는 데 의미가 있어.
- `지금은 지금`, `관계의 거리을`, 반말 캐릭터의 존댓말 혼합 같은 오류는 20대 유저 입장에서 바로 "AI가 대충 만든 답변 같다"로 읽혀. 이걸 테스트로 막은 건 소비자 신뢰에 좋아.
- `아웃풋` 같은 단어를 차단 목록에 넣은 것도 좋아. 사주 상담에서 이런 외래어가 튀어나오면 갑자기 업무 코칭 문서처럼 느껴져서 감성 몰입이 깨질 수 있어.

## 유료 사용 의향
- 무료 3회 상담 사용 의향: 9.4/10
- 2,900원 스타터 결제 의향: 8.4/10
- 월 9,900원/50별 구독 의향: 7.1/10
- 상담 품질 코드 기준 준비도: 8.5/10
- 실제 production 유료 전환 준비도: 7.2/10

## 소비자 결제 판단
- 나는 무료 3회는 써볼 것 같아. 첫 진입 분위기와 가격 구조는 부담이 낮고, 지금까지 기본 기능도 정상 기록이 많아졌어.
- 2,900원 스타터는 첫 답변이 30초 안에 오고, 캐릭터 말투가 확실히 다르면 결제할 가능성이 높아.
- 반대로 첫 답변이 40~50초 걸리면 가격이 2,900원이어도 망설일 것 같아. "돈 내면 더 빠르고 안정적일까?"가 아니라 "결제해도 이렇게 느리면 어떡하지?"로 생각이 바뀌거든.
- 월 구독은 아직 첫날 결제보다는 며칠 써본 뒤 판단할 가능성이 커. 답변 속도, 이전 상담 기억, 오늘피드/월간 리포트 가치가 반복해서 느껴져야 해.

## 좋아진 점
- live QA 스크립트가 `initial-analysis-prompts.mjs`를 import하게 되어, 구버전 중복 프롬프트 문제를 줄였어.
- `/api/saju/chat`이 첫 assistant turn이면 userText가 정확히 최신 prompt와 일치하지 않아도 첫 상담으로 처리하게 바뀐 점은 실사용 안정성에 좋아.
- fallback이 캐릭터별 opening과 행동 구조로 분리되어, 공통 안전문장 반복이 줄어들 가능성이 커졌어.
- `현우`의 `지금은 지금`, `지안`의 `관계의 거리을`, 반말 캐릭터 존댓말 혼합을 테스트로 잡은 점은 실제 문장 품질에 좋아.
- 품질 게이트에 `아웃풋`이 추가되어, 20대 일반 유저에게 어색한 외래어가 상담 초반에 튀어나오는 리스크가 줄었어.

## 아직 아쉬운 점
- 이번 수정 후 production live QA 통과 기록은 아직 확인하지 못했어. 코드와 테스트 방향은 좋아졌지만, 실제 배포에서 free/full live QA가 모두 `ok: true`인지 봐야 해.
- 직전 관찰값 기준 응답 시간이 37.9초~52.9초였고, 이건 20대 유저의 첫 상담 경험 기준으로 아직 길어.
- fallback이 더 좋아졌어도, 실제 provider가 자주 fallback으로 빠지면 "상담사가 깊게 봐준다"보다 "안전한 템플릿을 준다"로 느껴질 수 있어.
- 7개 캐릭터 각각 3회 이상 반복 QA가 아직 중요해. 1회 통과만으로는 도윤 503 같은 간헐 문제나 캐릭터별 말투 흔들림을 잡기 어려워.
- 결제 관점에서는 여전히 Paddle env, signed webhook, 스타터 첫 결제 1회 제한 같은 유료 gate가 닫혀야 해.

## 개발자 전달 우선순위
1. 최신 수정 배포 후 `QA_SCENARIO=free-only`와 full live QA를 production에서 다시 돌려야 해.
2. 7개 캐릭터를 각각 최소 3회 반복해서 HTTP 200, assistant 저장, 별 차감, 2문단, 마지막 질문, 오늘 행동, 쉬운 말, 캐릭터 말투를 같이 봐야 해.
3. 응답 시간은 첫 의미 있는 표시 15초 안쪽, 전체 완료 30초 안쪽을 목표로 다시 측정해야 해.
4. live QA 결과에 latency, fallback 여부, provider timeout 여부를 반드시 남겨야 해.
5. fallback 비율이 높으면 캐릭터별 fallback을 더 다듬기보다 provider 호출/timeout/재시도 전략을 먼저 봐야 해.
6. 결제는 여전히 열지 말고, Paddle production env와 signed webhook QA가 닫힌 뒤 스타터 2,900원 전환을 테스트해야 해.

## 최종 판단
- 이번 수정은 20대 여성 유저 관점에서 상담 신뢰를 높이는 좋은 수정이야.
- 특히 "테스트는 통과했는데 실제 앱은 다른 답을 하는" 불안과 "상담사들이 똑같이 말하는" 느낌을 줄이는 방향이라 제품 완성도에 의미가 있어.
- 하지만 유료 전환 관점에서는 아직 속도가 가장 큰 벽이야.
- 무료 베타로는 계속 보여줄 만하지만, 유료 오픈은 최신 production live QA 통과와 응답 시간 개선을 확인한 뒤가 맞아.
